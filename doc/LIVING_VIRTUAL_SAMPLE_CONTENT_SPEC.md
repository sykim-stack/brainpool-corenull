# 거실 가상 샘플 집·방·게시글 노출 설계서

- 상태: 구현 전 설계 기준
- 범위: CoreNull 거실의 초기 빈 콘텐츠 표현
- 기준 화면: 탑메뉴 → 거실 히어로 → 프로필 히어로/나이테 → 프로필/방 만들기 → 복도 `1 | 1` → 최신글 벽돌 배열 `3-2-3-2-3`
- 핵심: 새 저장 구조를 만들지 않고, 하드코딩된 샘플을 기존 화면의 임시 View 데이터로 조립한다.

## 1. 목적

실제 집·방·게시글이 아직 적은 초기에 발생하는 빈집 느낌을 줄인다. 설명 문구를 추가하는 대신, 샘플 집의 이미지와 방별 샘플 게시글을 통해 거실이 어떤 공간인지 직접 보여준다. 샘플은 실제 콘텐츠가 생기면 자리를 내준다.

샘플은 디자인·초기 경험을 위한 화면 자산이다. 실제 사용자 메시지나 활동 기록이 아니다.

## 2. 고정 원칙

1. **Message 원본은 하나다.** 샘플은 화면 렌더링용 하드코딩 데이터이며 `messages` 또는 다른 DB에 쓰지 않는다.
2. 샘플은 API를 호출하거나 Core 간 전달·복제를 하지 않는다.
3. 실제 메시지 수, 실제 방 수, 집 숙성도 나이테, 댓글·관심·저장·분석에 샘플을 포함하지 않는다.
4. CoreHub가 나이테에 연결되면 나이테는 CoreHub가 제공하는 실제 숙성도 표현을 따른다. 샘플 노출을 위해 나이테를 계산하거나 성장시키지 않는다.
5. 탑메뉴 색상은 CoreRing 기준을 확인하기 전까지 변경하지 않는다.
6. 기존 거실 레이아웃과 카드 패턴을 유지한다. 새 페이지, 새 DB 테이블, 새 API, 샘플 전용 시스템은 만들지 않는다.
7. 안내 문장(예: “이런 글을 써보세요”)은 넣지 않는다. 샘플을 가리키는 짧은 `샘플` 표시만 허용한다.

## 3. 현행 구현에 연결하는 위치

현재 코드에서 거실은 다음 기존 컴포넌트 조합으로 구성된다.

- `app/living/page.tsx`: 집·방·실제 메시지를 불러오고 View 데이터를 준비한다.
- `components/blocks/LivingBlock.tsx`: Hero, 복도, 최신글을 고정 순서로 렌더링한다.
- `components/blocks/NeighborContentBlock.tsx`: 복도에서 방 이름/이미지와 방별 `latestPost`를 함께 표시한다. 현재 거실은 `roomsPerPage={1}`이다.
- `components/blocks/MyContentBlock.tsx`: `layout="brick"`으로 최신글을 표시한다.
- `lib/brickLayout.ts`: 데스크톱 `3-2-3-2-3`, 모바일 `2-1-2-1-2` 배열 규칙을 제공한다.

샘플은 위 컴포넌트에 전달되는 화면 데이터에만 들어간다. 기존 실제 데이터 경로와 카드 배열 규칙은 유지한다.

## 4. 샘플 자산 구성

샘플은 완결된 **샘플 집 세트** 단위로 하드코딩한다. 세트마다 다음이 한 덩어리로 준비된다.

- 집 표시용 이름·대표 이미지·거실 배경 이미지
- 샘플 방 여러 개: 방 이름, 복도 이미지, 방 분위기
- 각 방의 고유 샘플 게시글: 본문과 승인된 샘플 미디어
- 각 게시글의 방 소속 및 최신글 정렬 순서

처음부터 많은 세트를 만들 필요는 없다. 실제 화면에서 서로 다른 분위기가 보이도록 3~4개 세트로 시작하고, 각 세트는 현재 데스크톱 한 페이지를 채울 수 있는 게시글 묶음을 포함한다. `3-2-3-2-3` 배열은 `partitionBrick`의 기존 규칙으로만 표시하며, 임의 카드 수에 맞춘 새 배열을 만들지 않는다. 미디어는 프로젝트에서 사용 허가된 기존 자산을 우선 활용하고, 실제 사용자 사진을 샘플처럼 재사용하지 않는다.

샘플은 임의의 사람·가족의 실제 활동을 흉내 내지 않는 일반적인 소재와 가상의 문장으로 구성한다. 이름·장소·날짜·댓글 수를 실제 사건처럼 꾸며내지 않는다.

## 5. 노출 및 전환 규칙

### 5.1 초기 선택

- 샘플 세트는 브라우저 렌더링이 준비되고 실제 데이터 로딩이 끝난 뒤 한 번 선택한다. 서버 렌더링과 클라이언트 렌더링의 랜덤 불일치나 화면 깜박임을 피한다.
- 샘플 세트 선택은 `owner_key`(기존 브라우저 식별자)와 샘플 세트 버전을 사용한 안정적인 의사랜덤 선택으로 한다. 따라서 다른 사용자에게는 서로 다른 세트가 분포될 수 있지만, 같은 사용자의 새로고침마다 장면이 바뀌지는 않는다.
- 샘플 세트 버전이 바뀌면 새 선택이 가능하다. 별도 DB 기록이나 새 API는 두지 않는다.
- 현재 집이 있으면 프로필·집 이름·나이테 등 실제 집 정보를 유지한다. 샘플은 거실의 복도·방·게시글 표현을 채운다. 집 데이터가 없는 경우 샘플 집을 실제 사용자 집처럼 생성하거나 저장하지 않는다.

### 5.2 샘플 노출 조건

- 현재 선택된 실제 집의 `type=comment`가 아닌 실제 상위 게시 메시지가 하나도 없을 때 샘플 집 세트를 노출한다.
- 실제 방이 이미 있지만 아직 실제 게시글이 없는 경우에도, 초기 빈 콘텐츠 장면으로 샘플 세트를 노출할 수 있다. 다만 샘플 방을 실제 방으로 생성하거나 실제 방 이름/ID에 연결하지 않는다.
- `owner_key`가 없거나 데이터 로딩에 실패한 경우에는 샘플 조건으로 간주하지 않는다. 오류·비인증 상태를 빈집 상태로 오인해 샘플을 노출하지 않는다.
- 로딩 중에는 샘플을 먼저 보여주지 않는다. 실제 게시글을 확인하기 전에 샘플이 잠깐 나타나는 깜박임을 막는다.

### 5.3 실제 게시글 발생 시

- 현재 집에 실제 상위 게시 메시지(`type=post`, 또는 저장 규칙상 실제 게시물로 표시되는 대응 타입)가 하나라도 확인되면 **샘플 세트 전체를 거실에서 제거**한다.
- 댓글(`type=comment`)만 생긴 경우에는 원 게시글이 실제 게시글이므로 샘플 상태를 해제한다. 댓글 자체를 샘플 피드 카드로 취급하지 않는다.
- 샘플과 실제 콘텐츠를 최신글 목록에서 섞어 보여주지 않는다. 첫 실제 게시글 시점부터 실제 데이터만 표시한다.
- 샘플 제거 후에는 실제 방의 복도 카드와 실제 메시지 목록만 렌더링한다. 아직 실제 방/게시글이 적더라도 빈 공간은 기존 empty state와 레이아웃이 담당한다.
- 상태는 실제 데이터 조회 결과로 결정한다. 샘플 게시글 작성 완료 같은 가짜 이벤트나 DB 쓰기 동작은 없다.

> 위 규칙은 “게시글이 생기면 샘플이 사라진다”를 **현재 집의 첫 실제 게시글이 생기면 샘플 집 세트를 통째로 종료**하는 것으로 구체화한 것이다. 방별 샘플은 방의 분위기와 게시글을 짝지어 보여주기 위한 콘텐츠 구조이지, 방마다 서로 다른 종료 상태를 저장하는 기능이 아니다.

## 6. 화면 표현 및 상호작용

### 거실 히어로 / 프로필 / 나이테

- 실제 사용자의 집이 있으면 그 집의 프로필·대표 사진·이름을 그대로 보여준다.
- 나이테는 샘플 수나 샘플 방을 반영하지 않는다. 향후 CoreHub 연동 시 실제 숙성도 값만 사용한다.
- 샘플 세트의 대표 이미지를 거실 히어로 배경 후보로 쓰더라도 실제 집의 대표 사진이나 프로필 정보인 것처럼 덮어쓰지 않는다. 시각적 배경 사용 여부는 실제 집 이미지의 우선권을 보장한다.

### 복도 `1 | 1`

- 기존처럼 방 하나를 선택해 `복도 이미지(방 이름) | 그 방의 최신글`로 쌍을 맞춘다.
- 샘플 세트가 활성화된 동안에는 선택된 샘플 방과 해당 방의 샘플 최신글을 함께 표시한다.
- 방을 넘기면 같은 세트의 다음 방과 그 방에 속한 게시글로 이동한다. 방 이름·이미지와 게시글의 연결은 유지한다.

### 최신글 `3-2-3-2-3`

- 샘플 세트의 게시글을 기존 `MyContentBlock` 및 `partitionBrick`으로 표시한다.
- 실제 게시글과 샘플 게시글을 혼합하지 않는다.
- 배열, 카드 폭·높이, 페이지 전환 동작을 이 기능만을 위해 변경하지 않는다.

### 샘플임을 구분하고 가짜 활동을 방지

- 카드에는 작은 `샘플` 배지를 표시한다. 긴 안내 문구는 쓰지 않는다.
- 샘플 카드에는 실제 게시물 상세 이동, 댓글 작성, 댓글 수, 관심/저장, 공유, 인라인 댓글 입력을 제공하지 않는다. 버튼을 비활성화해 놓고 실제 게시글처럼 보이게 하지 않는다.
- 샘플에는 실제 시간 흐름으로 오해될 상대 날짜(“방금 전”, “어제”)와 가짜 반응 수를 표시하지 않는다.
- 샘플 표시를 위해 실제 메시지 데이터 타입이나 `messages` 행을 만들지 않는다. 필요한 렌더링 구분은 View 계층의 샘플 표시 정보로 처리한다.

## 7. 데이터와 로직의 경계

샘플은 정적 코드 자산이다. 구현 시 기존 페이지의 데이터 조립 단계에서 아래의 순서만 따른다.

1. 실제 owner/house/rooms/messages를 현재 API로 조회한다.
2. 로딩/오류/비인증을 실제 빈 상태와 구분한다.
3. 실제 상위 게시 메시지가 존재하면 기존 실데이터 View를 그대로 만든다.
4. 실제 게시물이 없고 정상적인 빈집 상태라면 선택된 샘플 세트에서 `NeighborChip[]`과 `PostBlockData[]`에 대응하는 View 데이터를 만든다.
5. 그 결과를 기존 `LivingBlock`에 전달한다.

이 문서는 세부 구현 함수 이름이나 새 전역 상태를 고정하지 않는다. 샘플의 세트 선택과 데이터 변환은 재사용 가능한 작은 함수/상수로 구현하되, 별도 엔진·테이블·API·상태 관리 서비스로 확대하지 않는다.

## 8. 오류·경계 상황

| 상태 | 표시 규칙 |
|---|---|
| 실제 데이터 로딩 중 | 기존 로딩 상태만 표시, 샘플 미노출 |
| 정상 조회 + 실제 글 0개 | 샘플 세트 표시 |
| 실제 글 1개 이상 | 샘플 전체 숨김, 실제 콘텐츠만 표시 |
| 네트워크/API 오류 | 샘플로 대체하지 않음. 기존 오류/빈 상태 처리 유지 |
| owner 식별 불가 | 사용자 집/샘플 집을 생성하지 않음 |
| 실제 방은 있으나 게시글 없음 | 실제 방은 실제 데이터로 표시하고, 집 전체에 실제 게시글이 0개인 동안 샘플 화면 정책을 적용 |
| 샘플 자산 누락 | 누락 미디어는 기존 fallback 이미지/표현으로 처리, 잘못된 실제 데이터 생성 금지 |
| 샘플 선택 후 실제 글 작성 | 다음 데이터 갱신 시 즉시 실데이터로 전환; 화면 새로고침을 강제하지 않음 |

## 9. 수용 기준

- [ ] 새 테이블·컬럼·API·DB 행이 추가되지 않는다.
- [ ] 실제 게시글이 없는 정상 초기 거실에서만 샘플 집/방/게시글이 보인다.
- [ ] 화면 새로고침만으로 동일 사용자 샘플 장면이 불필요하게 바뀌지 않는다.
- [ ] 다른 사용자에게는 여러 샘플 세트가 분포된다.
- [ ] 복도에서 방 이미지·방 이름·방 최신글이 정확히 한 방 단위로 짝지어진다.
- [ ] 최신글은 기존 데스크톱 `3-2-3-2-3`, 모바일 `2-1-2-1-2` 패턴을 사용한다.
- [ ] 실제 게시글이 하나 생기면 다음 렌더에서 모든 샘플이 사라지고 실제 콘텐츠만 남는다.
- [ ] 댓글만 샘플 카드로 노출되지 않으며, 댓글은 실제 부모 게시글의 존재와 함께 샘플 종료 조건에 반영된다.
- [ ] 샘플은 DB·실제 게시글 수·방 수·나이테·관심/댓글 상태에 영향을 주지 않는다.
- [ ] 샘플 카드에 실제 게시글로 오해할 날짜·반응·상세 동작이 없다.
- [ ] API 오류와 로딩 상태가 샘플 조건으로 오인되지 않는다.
- [ ] 탑메뉴 색상과 거실의 고정 레이아웃은 이 변경에서 수정되지 않는다.

## 10. 제외 범위

- CoreHub의 나이테 산출·의미 분석 구현
- CoreRing 색상에 맞춘 탑메뉴 변경
- 실제 방/집 자동 생성 및 샘플 데이터 DB 저장
- Core 간 직접 연결·전달·중복 저장
- 새 빈 상태 페이지 또는 안내 문구 추가
- 거실의 복도/최신글 순서, 카드 레이아웃, brick 패턴 변경

## 11. 확인이 필요한 콘텐츠 선택

구조 결정은 위와 같이 닫고, 구현 전에 콘텐츠만 확정하면 된다.

- 샘플 세트의 분위기 및 방 이름
- 샘플 게시글의 한국어/다국어 구성 여부
- 사용할 수 있는 프로젝트 승인 이미지
- 첫 버전에 넣을 샘플 세트 수
